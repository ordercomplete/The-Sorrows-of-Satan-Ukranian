ЧАСТИНА I. УМОВИ ПРАВИЛЬНОЇ ІНСТАЛЯЦІЇ
================================================================

----------------------------------------------------------------
1. ДЖЕРЕЛО ІСТИНИ ТА ШЛЯХИ
----------------------------------------------------------------
- Центральне репо Агента = джерело канонічних файлів.
- Уся конфігурація Агента живе в папці `agent_config/` (ВКЛЮЧНО з
  `manifest.json`, скриптами, шаблонами).
- `manifest.json` читається виконавцем ІЗ `agent_config/manifest.json`,
  а НЕ з кореня проєкту.
- `opencode.json` ЗАЛИШАЄТЬСЯ в корені (вимога LM Studio Code) —
  синхронізація копіює/поновлює його, але не чіпає інших файлів кореня.

----------------------------------------------------------------
2. БЕЗКОНФЛІКТНІСТЬ (схема v1.4.0)
----------------------------------------------------------------
- Кореневий `.gitignore` цільового проєкту НЕ перезаписується і НЕ
  змінюється. Натомість кожна папка Агента несе власний локальний
  `.gitignore` (правила `.gitignore` діють лише на своє піддерево,
  тому вони не конфліктують з правилами хост-проєкту):
    AGENT/.gitignore          — __pycache__/, *.pyc, state/, *.log, trash/
    .github/.gitignore        — __pycache__/, *.pyc, state/, *.log
    .clinerules/.gitignore    — те саме
    .continue/.gitignore      — те саме
    trash/.gitignore          — усе, крім .gitignore і deletion_log.md
  Усі вони розповсюджуються автоматично через manifest.json.
- Кореневий .gitignore ЦЕНТРАЛЬНОГО репо — тільки для самого репо: у хост-проєкти
  не розсилається і не мержиться (manifest не містить запису на корінь хоста).
- agent-lock.json у корені хост-проєкту свідомо НЕ ігнорується: його комітять,
  на ньому базуються команди sync-agent.py status/remove/gitignore.
- Кореневий .gitignore у хост-проєкті НЕ генерується: всі артефакти Агента покриті
  локальними .gitignore папок; єдиний кореневий артефакт — agent-lock.json, який
  свідомо комітиться.
- Вже відстежені хостом файли ігнор-правила НЕ «розтрекують» —
   ризик зіпсувати історію хоста відсутній.
- **`agent-lock.json`** (створюється автоматично після `--apply` у корені
  цільового проєкту) фіксує всі встановлені файли Агента за типами
  (`copy_full`, `stub`, `root_files`) з хешами. Команди `sync-agent.py`:
    python agent_config/scripts/sync-agent.py status    # стан: OK/Modified/Missing/New
    python agent_config/scripts/sync-agent.py status --verbose   # детальний список
    python agent_config/scripts/sync-agent.py remove    # видалення ЛИШЕ Agent-файлів (через Корзину), --force щоб прибрати й змінені
    python agent_config/scripts/sync-agent.py gitignore # гарантує локальні .gitignore папок Агента
  Команда `gitignore` та `--apply` НЕ змінюють кореневий `.gitignore`
  цільового проєкту — ігнор-правила Агента живуть у локальних
  `.gitignore` папок (див. вище). `remove` переносить файли у Корзину
  (файли Агента → `AGENT/trash/`, проєктні → `trash/` у корені).


----------------------------------------------------------------
3. ДВІ КОРЗИНИ (видалення тільки через них)
----------------------------------------------------------------
- AGENT/trash/        — файли АГЕНТА (структура Агента: папки AGENT/ .github/
                        .clinerules/ .continue/ .opencode/ agent_config/, а
                        найточніше — target_paths з agent_config/manifest.json);
                        лог: AGENT/trash/deletion_log.md
- trash/ (у корені)   — файли ПРОЄКТУ (решту, крім структури Агента);
                        лог: trash/deletion_log.md
- Маршрутизація автоматична: manifest.json → папки Агента → fallback за шляхом.

4. УМОВИ СЕРЕДОВИЩА (обов'язкові) — встановити + перевірити
----------------------------------------------------------------
Потрібно: Python 3.8+ (ліпше 3.12+ для anti_loop.py), git.
На Windows ще потрібен PowerShell 5.1+ або bash (Git Bash / WSL).

--- Python ---

  Встановити:
    Windows (winget):     winget install Python.Python.3.12
    Windows (веб):        https://www.python.org/downloads/windows/
                             (Під час встановлення відзнач: "Add Python to PATH")
    Windows (choco):      choco install python --version 3.12
    Linux (Debian/Ubuntu):  sudo apt update && sudo apt install python3 python3-pip
    Linux (Fedora/RHEL):      sudo dnf install python3 python3-pip
    Linux (Arch):             sudo pacman -S python python-pip
    macOS (brew):             brew install python@3.12

  Перевірити:
    Windows:  python --version        # має бути 3.8+
    Linux:    python3 --version
    macOS:    python3 --version

--- Git ---

  Встановити:
    Windows (winget):     winget install Git.Git
    Windows (веб):        https://git-scm.com/download/win
    Linux (Debian/Ubuntu):  sudo apt install git
    Linux (Fedora/RHEL):    sudo dnf install git
    macOS (brew):           brew install git

  Перевірити:
    Windows:  git --version
    Linux:    git --version
    macOS:    git --version

--- PowerShell (тільки Windows) ---

  Встановити:
    Windows 10/11: вбудований.
    Якщо не встановлен: winget install Microsoft.PowerShell

  Перевірити:
    powershell -Command "$PSVersionTable.PSVersion"   # має бути 5.1+ або 7+

--- Bash (Linux/macOS або Git Bash на Windows) ---

  Встановити:
    Windows:  встановіться разом із Git (https://git-scm.com/download/win)
              або використовуйте WSL: wsl --install
    Linux:    вбудований (встановлюється разом із ОС)
    macOS:    вбудований (Terminal) або: xcode-select --install

  Перевірити:
    bash --version    # має бути bash 4+

--- Підсумкова перевірка середовища ---

  # Всі команди мають вивести версію без помилок:
  python --version       (або python3 --version)
  git --version
  powershell -Command "$PSVersionTable.PSVersion"   (Windows)
  bash --version

5. УМОВИ ЦІЛЬОВОГО ПРОЄКТУ
----------------------------------------------------------------
- Цільова папка — новий проєкт або існуючий (конфліктів по шляхах
  бути не має: локальні .gitignore не перетинаються з коренем хоста).
- Не запускай встановлення в проєкт з незакоміченими змінами, які
  не хочеш втратити (спершу `git status`, коміти).

6. УМОВИ ЗАПУСКУ (безпека)
----------------------------------------------------------------
- Спершу ЗАВЖДИ `--dry-run` (показати що зміниться), проаналізуй список.
- `--apply` — лише після перегляду dry-run і за згодою користувача.
- Файли вручну не видаляй — тільки через Корзину (ЧАСТИНА V).

ЧАСТИНА II. ПОКРОКОВА ІНСТАЛЯЦІЯ (НОВИЙ ПРОЄКТ)
================================================================

СПОСІБ A — автоматичний інсталятор (рекомендовано)
----------------------------------------------------------------
Крок 0. Відкрий термінал у корені цільового проєкту.

Windows (PowerShell):
  powershell -ExecutionPolicy Bypass -File agent_config\scripts\install.ps1

Linux / macOS / Git Bash:
  bash agent_config/scripts/install.sh

Інсталятор сам: клонує центральне репо у temp → копіює ядро AGENT/ →
показує dry-run → застосовує синхронізацію → запускає перевірки →
прибирає temp. Свій URL репо можна передати першим аргументом:
  bash agent_config/scripts/install.sh https://github.com/<user>/<repo>.git

СПОСІБ B — ручна інсталяція через sync-agent.py
----------------------------------------------------------------
Крок 1. Склонуй центральне репо ПОРЯД (поза цільовим проєктом):
  git clone https://github.com/ordercomplete/Comfy-smart-lady-agent.git ../csl-agent

Крок 2. Перевір середовище:
  python --version      # 3.8+
  git --version

Крок 3. Dry-run — ПОДИВИСЬ, що зміниться у твоєму проєкті:
  python ../csl-agent/agent_config/scripts/sync-agent.py --source ../csl-agent --target . --dry-run

Крок 4. Застосуй синхронізацію (копіює AGENT/, .github/, .clinerules/,
.continue/, .opencode/, agent_config/, opencode.json, локальні .gitignore):
  python ../csl-agent/agent_config/scripts/sync-agent.py --source ../csl-agent --target . --apply

Крок 5. Перевір результат (ЧАСТИНА IV).

================================================================
ЧАСТИНА III.1. ПЕРЕВСТАНОВЛЕННЯ (REINSTALL)
================================================================

Команда перевстановлення повністю очищає ВСІ файли Агента
(без Корзини) і встановлює чисту копію з джерела.

3.1. Перевірка що станеться (dry-run, без змін):
  python agent_config/scripts/sync-agent.py reinstall --dry-run

3.2. Повне перевстановлення з GitHub (авто-клон):
  python agent_config/scripts/sync-agent.py reinstall

3.3. Перевстановлення з локального репо:
  python agent_config/scripts/sync-agent.py reinstall --source ~/repos/Comfy-smart-lady-agent

3.4. Повне перевстановлення з примусовим видаленням модифікованих файлів:
  python agent_config/scripts/sync-agent.py reinstall --force

3.5. Повне видалення без Корзини (purge):
  python agent_config/scripts/sync-agent.py remove --purge
  # з примусовим видаленням модифікованих файлів:
  python agent_config/scripts/sync-agent.py remove --purge --force

4 ЕТАПИ reinstall:
  1/4 PURGE   — видаляє ВСІ файли Агента (Path.unlink(), bypass trash)
                згідно manifest.json + AGENT_DIRS, --force для модифікованих
  2/4 SOURCE  — визначає джерело: якщо --source не вказаний або не існує
                локально → авто-клон з GitHub (git clone --depth 1)
  3/4 INSTALL — sync-agent.py --apply з тимчасового/локального джерела.
                Копіює ядро AGENT/, файли manifest, root_files, stub-файли.
                Створює новий agent-lock.json
  4/4 VERIFY  — gitignore → status --verbose → py_compile всіх критичних
                файлів (anti_loop.py, watch_agent_file.py, str.translate.py,
                agent_startup.py, delete_to_trash.py, sync-agent.py)

РЕКОМЕНДАЦІЇ:
  - Завжди спочатку запускайте --dry-run, щоб побачити які файли будуть
    видалені/змінені
  - Бэкапуйте модифіковані файли вручну (reinstall видаляє ВСІ Agent-файли)
  - Перевіряйте status --verbose після reinstall — гарантує що всі файли на місці
  - Для чистого інсталятора використовується remove --purge, а не звичайний
    remove (який переносить у Корзину)

ЧАСТИНА V. ПОВСЯКДЕННА РОБОТА ПІСЛЯ УСТАНОВКИ
================================================================
1. Оновлення manifest після додавання нових файлів Агента
   (нові скіли/хуки/скрипти в AGENT/ або зміни в agent_config/):
  python agent_config/scripts/update-manifest.py --dry-run   # спершу подивитись
  python agent_config/scripts/update-manifest.py --apply     # перезаписати manifest.json

2. Видалення файлів — ТІЛЬКИ через Корзину (дві, маршрутизація авто):
  # файл Агента → AGENT/trash/
  python agent_config/scripts/delete_to_trash.py AGENT/<шлях> --reason "причина"
  # файл проєкту → trash/ у корені
  python agent_config/scripts/delete_to_trash.py <шлях> --reason "причина"
  # спершу можна подивитись без переносу:
  python agent_config/scripts/delete_to_trash.py <шлях> --dry-run

3. Синхронізація змін канону в оболонки чатів (.github/.clinerules/
   .continue/.opencode) після редагування файлів AGENT/:
  python agent_config/scripts/sync-agent.py --source <шлях_до_репо> --target . --apply

4. Перевірка оновлень (режим notify, без змін):
  - При кожному старті агента (agent_startup.py) тихо дивиться git HEAD
    Центрального репо (raw.githubusercontent → або shallow git clone для
    приватних репо) і порівнює agent_config/VERSION;
  - не частіше ніж 1 раз на `interval_hours` (24) — кеш у AGENT/state/update_check.json;
  - мережеві помилки/офлайн мовчки ігноруються (старт агента ніколи не блокується);
  - ручна перевірка:
      python agent_config/scripts/sync-agent.py --check-update
    Повертає код 10, якщо нова версія (і друкує підказку --update).

5. Статус встановлення та видалення Агента (через agent-lock.json):
  # стан: OK / Modified / Missing / New
  python agent_config/scripts/sync-agent.py status --verbose
  # видалення ЛИШЕ Agent-файлів (через Корзину: AGENT/* → AGENT/trash/, решта → trash/)
  python agent_config/scripts/sync-agent.py remove
  # забезпечити локальні .gitignore папок Агента (корінь проєкту не чіпається)
  python agent_config/scripts/sync-agent.py gitignore
