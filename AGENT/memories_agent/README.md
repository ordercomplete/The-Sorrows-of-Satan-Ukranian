# 🧠 Внутрішня історія Агента Comfy-smart-lady

## Призначення
Ця папка зберігає **внутрішні логи процесів самого агента**, окремо від `memories/session/` (зовнішні процеси проєкту) та `memories/repo/action-log_YYYY-MM-DD.md` (зовнішні дії).

## Структура

```
memories_agent/
├── README.md              # Цей файл — інструкція ведення
├── migration-note.md      # Нотатка про міграцію memories → memories_agent (2026-08-20)
├── session/session_YYYY-MM-DD.md       # Історія внутрішніх сесій агента
├── errors/error-log_YYYY-MM-DD.md      # Помилки, цикли, збої системи
├── actions/action-log_YYYY-MM-DD.md    # Детальний журнал дій агента
├── config-changes/changes_log.md       # Зміни в конфігурації, інструкціях, скриптах
└── cross-reference/external-links.md   # Крос-референс із загальними процесами проєкту
```

---

## Файли та формати

### 1. `session/session_YYYY-MM-DD.md` — Історія внутрішніх сесій
**Хто веде:** сам агент Comfy-smart-lady
**Що записує:** події пов'язані з внутрішніми процесами агента: анти-цикл, перезавантаження контексту, зміни в інструкціях, завантаження скриптів.

```markdown
# Сесія YYYY-MM-DD
- **HH:MM** — [подія: запуск, анти-цикл, зміна інструкцій...]
- **Статус:** в-процесі / завершено
```

---

### 2. `errors/error-log_YYYY-MM-DD.md` — Помилки та цикли агента
**Хто веде:** автоматично через `AGENT/scripts/anti_loop.py` та вручну агентом
**Що записує:** збої системи, анти-loop події, помилки виконання команд, конфлікт інструкцій.

```markdown
### 🔴/⚠️ [Назва події]
**Час:** YYYY-MM-DD HH:MM
**Tool / Процес:** [назва tool або процесу]
**Ціль / Суть:** [короткий опис]
**Причина:** [чому сталося]
**Дія:** [яку дію виконано або пропонується]
```

---

### 3. `actions/action-log_YYYY-MM-DD.md` — Детальний журнал дій агента
**Хто веде:** агент вручну під час роботи
**Що записує:** внутрішні дії агента, інсайти, успіхи/невдачі виконання інструкцій.

```markdown
### ✅/❌/💡 [Назва дії]
**Час:** YYYY-MM-DD HH:MM
- [що зроблено / інсайт]
```

## Правила ведення

### ✅ Коли записувати в `session/session_YYYY-MM-DD.md`:
- **На початку сесії** — створити файл із датою початку та статусом "в-процесі"
- **Під час роботи** — додавати події з міткою часу у кінець файлу
- **При анти-loop спрацюванні** — записати детально що спрацювало і як
- **В кінці сесії** — оновити статус на "завершено"

### ✅ Коли записувати в `errors/error-log_YYYY-MM-DD.md`:
- **Автоматично** через `AGENT/scripts/anti_loop.py` при детекції циклів
- **Вручну агентом** коли бачить:
  - Збій виконання команди (наприклад, не знайдено файл)
  - Конфлікт інструкцій або помилку в логіці
  - Помилку синтаксису при читанні/редагуванні коду

### ✅ Коли записувати в `actions/action-log_YYYY-MM-DD.md`:
- **Успішні дії** — що спрацювало і чому (з поясненням)
- **Невдалі спроби** — що не вийшло і причина
- **Інсайти** — цікаві патерни, висновки, нове знання про систему агента

---

## Іконки статусу:
- 🟢 **Вже працює / успіх** — позитивний результат
- ⚠️ **Проблема / помилка** — негативний статус, потребує уваги
- 🔴 **Цикл / збій** — критична подія (анти-loop, конфлікт)
- 💡 **Інсайт** — нове знання або патерн

---

## Розділення логів: `memories/` vs `memories_agent/`

| Лог | Внутрішній (memories_agent/) | Зовнішній (memories/ у хост-проєкті) |
|-----|------------------------------|--------------------------------------|
| session/ | Сесії агента: анти-loop, перезавантаження контексту | Зовнішні процеси проєкту (агент + користувач) |
| errors/ | Збої та цикли самого агента (авто-хук + вручну) | Помилки зовнішніх процесів проєкту |
| actions/ | Детальний журнал дій самого агента та інсайти | Дії назовні: читання файлів, команди, редагування коду |

---

## Заборони

- **НЕ видаляти** файли після завершення сесії — всі логи зберігаються як історія
- **НЕ змішувати** внутрішні та зовнішні логи в один файл — кожен тип логу веде у свою папку
- **НЕ роздувати** журнал — записувати тільки результати, інсайти та помилки, а не кожну дрібну дію
