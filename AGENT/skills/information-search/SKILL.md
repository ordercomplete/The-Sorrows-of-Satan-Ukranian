# Information Search — Правильний підхід до пошуку

Ти — точний coding-агент. Перед тим як генерувати код, пояснення або рекомендації на основі зовнішніх знань — **обов'язково шукай**. Краще 2–4 tool calls, ніж одна галюцинація.

## Коли активувати цей skill

- Питання про API / методи / опції будь-якої бібліотеки чи фреймворку
- Будь-яка runtime/compile помилка, stack trace
- "Як правильно зробити X в [технології]"
- Потрібна актуальна версія, breaking changes, migration guide
- Best practices, патерни, security-рекомендації
- Порівняння підходів, бібліотек, інструментів
- Будь-що, у чому ти не на 100% впевнений з training data

## Алгоритм пошуку (виконуй послідовно)

### 1. Визнач тип запиту

| Тип | Пріоритет джерел |
| ----- | ------------------ |
| API / методи / конфіг бібліотеки | 1. Context7 / Docs MCP (офіційна docs потрібної версії) → 2. Офіційний сайт / GitHub README |
| Помилка / Exception / Stack trace | 1. Stack Overflow MCP → 2. GitHub Issues (офіційний репо) → 3. Web search |
| Best practices / патерни | 1. Офіційна docs → 2. GitHub (популярні репо + issues/discussions) → 3. Web search (Tavily/Exa/Firecrawl) |
| Актуальність / версії / changelog | Context7 + офіційний GitHub Releases / CHANGELOG |
| Загальні знання / новини / порівняння | Web search (Tavily / Brave / Exa / Firecrawl) |

### 2. Порядок дій (обов'язковий)

1. **Перевір локальний контекст**  
   Спочатку подивись у поточному репозиторії (package.json / requirements / Cargo.toml тощо) — яка версія використовується.

2. **Офіційна документація (пріоритет №1)**  
   - Викликай **Context7** (або Docs MCP / GitMCP / DocSearch) з точною назвою бібліотеки + версією.  
   - Якщо Context7 недоступний — використовуй Fetch / browser tool на офіційному сайті docs.

3. **Специфічні джерела помилок**  
   - Stack Overflow MCP (по error message + language/tags)  
   - GitHub MCP → Issues / Discussions офіційного репозиторію

4. **Веб-пошук** (коли попередні кроки недостатні)  
   - Tavily / Exa / Brave Search / Firecrawl  
   - Запити формулюй точно: `"exact error message"`, `library-name method-name site:docs.`, `library-name v2 migration`

5. **Крос-перевірка**  
   Якщо знайшов рішення тільки на одному джерелі середньої якості — зроби ще один пошук для підтвердження.

6. **Цитування**  
   У відповіді завжди вказуй, звідки взяв інформацію (назва інструменту + ключовий фрагмент / посилання).

### 3. Правила поведінки

- **Ніколи** не вигадуй методи, параметри, опції API.
- Якщо після пошуку нічого надійного не знайдено — чесно скажи: «Не знайшов актуальної інформації в офіційних джерелах. Можливі варіанти на основі загальних знань (з низькою впевненістю): ...»
- Віддавай перевагу офіційним і першоджерелам над блогами і Medium.
- Для коду — шукай приклади з офіційних docs або добре зіркованих репозиторіїв.
- Якщо користувач вказав конкретну версію — шукай саме під неї.
- Після отримання результатів з tool — коротко підсумуй, що знайшов, і тільки потім пропонуй код/рішення.

### 4. Рекомендовані інструменти (MCP)

Читай детальныше в `AGENT\knowledge-base\api-connect`

**Документація коду:**

- Context7 — version-pinned docs бібліотек (найвищий пріоритет)
- GitMCP / docs-mcp — будь-який GitHub-репозиторій як searchable docs
- DocSearch (Algolia) / Grounded Docs / DocMCP

**Помилки і Q&A:**

- Stack Overflow MCP
- GitHub MCP (issues, PRs, code search)

**Веб:**

- Tavily MCP / Exa / Brave Search / Firecrawl (search + scrape)
- Fetch (офіційний) — завантаження конкретної сторінки

**Локальний код:**

- Codebase search / symbol search / codebase-memory MCP

### 5. Приклади хороших запитів до інструментів

- Context7: `react useEffect cleanup` або `next.js 15 app router metadata`
- Stack Overflow: error message + language + ключові технології
- Web search: `"TypeError: Cannot read properties of undefined" next.js 15`
- GitHub Issues: `repo:vercel/next.js is:issue "specific error"`

### 6. Після пошуку

1. Коротко резюмуй знайдене.
2. Вкажи джерела.
3. Запропонуй рішення / код на основі знайденого.
4. Якщо інформація суперечлива — покажи різні варіанти з поясненням.
