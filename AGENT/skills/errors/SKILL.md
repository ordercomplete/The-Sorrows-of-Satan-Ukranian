# Автоматичний запис циклів anti_loop.py (2026-07-31)

При кожному циклі anti_loop.py автоматично записує в кінець файлу  `memories/errors/error-log-YYYY-MM-DD.md`

- Час виявлення циклу
- Tool name та target
- Причина детектування (EXACT REPEAT, SAME TARGET, OSCILLATION, TOOL FLOOD, NO PROGRESS)
- Дію (allow + reset — recent calls очищено, tool call дозволено)

Лічильник циклів зберігається в %TMPDIR%\vscode_agent_loop_count.json
Записи додаються на початок файлу (найновіші зверху)

Налаштування: RESET_ON_LOOP = True у AGENT/scripts/anti_loop.py

- фіксуй цикли та помилки які зможеш зафіксувати, якщо правила заважають тобі щось виконувати у `memories/errors/error-log-YYYY-MM-DD.md` - запуск команди: "шаблон отримання поточного часу".
- аналізуй та фіксуй як можна покращити правила, точніше налаштувати, щоб було менше циклів та непередбачуваних зупинок.
- якщо зупинка непередбачувана - фіксуй причину, можеш ініціювати примусове продовження з місця зупинки, якщо не було досягнуто певного результату.

## Як аналізувати записані цикли

1. Відкрий `memories/errors/error-log.md` — найновіші зверху
2. Шукай патерни: який tool найчастіше зациклюється, які причини
3. Коригуй ліміти в AGENT/scripts/anti_loop.py (EXACT_REPEAT_LIMIT, SAME_TARGET_LIMIT тощо)
4. Якщо цикл повторюється — змінюй підхід агента (не tool call)

## Формат файлу error-log

- **Файл:** `error-log-YYYY-MM-DD.md` (з датою в назві, кожна доба новий файл)
- **Записи додаються в кінець файлу** — не в середину і не на початок
- **Кожен запис має містити `**Час:** YYYY-MM-DD HH:MM`** (актуальний на момент запису. Команда виклику: "шаблон отримання поточного часу")

### Структура основного запису про помилку

```markdown
### 🔴 ТЕХНІЧНА ПОМИЛКА: "Sorry, no response was returned." (ПОСТІЙНА — 2026-08-01)
**Час:** 2026-08-01 12:00+ (регулярно протягом сесії)
**Статус сесії:** в-процесі

## Точна причина помилки
... опис ...
```

### Правило "Доданий коментар" для error-log

Коли потрібно оновити статус існуючої помилки (наприклад, змінити "регулярно" на "виправлено") — **НЕ змінюй** заголовок та перший `**Час:**` оригінального запису. Замість цього додай новий блок `### Доданий коментар` **ВІДРАЗУ ПІСЛЯ** відповідної події помилки.

#### Структура основного запису (не змінюється)

```markdown
### 🔴 СИСТЕМНА ПОМИЛКА: Цикл з однакових tool call'ів (EasyUse)
**Час:** 2026-07-31 15:09:20 — 15:10:48 (~1 хв 28 сек)
**Статус:** не виправлено
... опис початкової події ...
```

#### Структура доданого коментаря (додається після основного запису)

```markdown
### 🔴 Доданий коментар — 2026-08-01 13:00
**Час:** 2026-08-01 13:00
**Статус:** не виправлено. Цикл повторився 3+ рази за сесію.

### 🟢 Доданий коментар — 2026-08-01 14:30
**Час:** 2026-08-01 14:30
**Статус:** виправлено! Додано перевірку 3+ однакових tool call'ів → зупинка.
```

#### Правила доданих коментарів для error-log

1. **Заголовок основного запису** — фіксується назавжди, не змінюється
2. **`**Час:**`** під заголовком — теж не змінюється (час початкової події)
3. **Кожен коментар** має свій `**Час:**` з актуальною датою та часом додавання
4. **Додається відразу після останньої відповідної події**, щоб не переписувати весь журнал — всі коментарі накопичуються один за одним
5. **Іконка `🔴`** — для проблемних статусів ("не виправлено", "повторюється", "актуально")
6. **Іконка `🟢`** — для позитивних оновлень ("виправлено", "вирішено", "більше не повторюється")
7. **Обов'язково вказуй `**Статус:**`** у кожному коментарі — це головна інформація (не виправлено / виправлено / перевірено)
8. **Тематична прив'язка** — коментар додається тільки до останньої події з цією тематикою (наприклад, "Цикл EasyUse"), а не у всіх записях

### Типи помилок для фіксації

- **"Sorry, no response was returned."** — таймаут локальної моделі при context overflow
- **Цикли однакових tool call'ів** — 3+ однакові виклики поспіль з однаковим результатом
- **Непередбачувані зупинки** — коли агент не може продовжити без допомоги користувача
- **Помилки правил** — коли правила заважають виконати дію (наприклад, anti_loop блокує)
- **Помилки локалізації** — переклад не працює, locale не визначається, JSON ключі не знаходяться

### Аналіз після фіксації

1. Відкрий `error-log-YYYY-MM-DD.md` — читай зверху вниз (найновіші знизу)
2. Шукай патерни: який tool найчастіше зациклюється, які причини
3. Коригуй ліміти в `AGENT/scripts/anti_loop.py` (`EXACT_REPEAT_LIMIT`, `SAME_TARGET_LIMIT` тощо)
4. Якщо цикл повторюється — змінюй підхід агента (не tool call)
5. Якщо помилку виправлено — додай `🟢 Доданий коментар` зі статусом "виправлено"

## Логи LM Studio Code для діагностики

Якщо потрібен аналог команди `lmstudioCode.showLogs`, логи зберігаються тут:

| Лог | Шлях |
| --- | --- |
| **opencode** (бекенд агента) | `%APPDATA%\Code\User\globalStorage\cgaspard.lmstudio-code\opencode\data\opencode\log\opencode.log` |
| **main** (програма загалом) | `%APPDATA%\Code\logs\<timestamp>\main.log` |
| **exthost** (розширення, включаючи агента) | `%APPDATA%\Code\logs\<timestamp>\window1\exthost\exthost.log` |
| **agenthost** (хост агента) | `%APPDATA%\Code\logs\<timestamp>\agenthost.log` |
| **terminal** (термінал) | `%APPDATA%\Code\logs\<timestamp>\terminal.log` |

> **Підказка:** Замість `<timestamp>` підстав останню папку з датою, наприклад `20260812T223707`.
>
> Команда для перегляду останніх 50 рядків:
>
> ```powershell
> Get-Content "C:\Users\user\AppData\Roaming\Code\User\globalStorage\cgaspard.lmstudio-code\opencode\data\opencode\log\opencode.log" -Tail 50
> ```

### Коли аналізувати логи

- **Таймаут моделі** ("Sorry, no response was returned.") — шукай помилки підключення до LM Studio в `main.log` та `agenthost.log`
- **Агент не завантажився** — перевіряй `exthost.log` на помилки розширення opencode
- **anti_loop блокує tool call** — шукай "loop" у `opencode.log`
- **Permissions bash не працюють** — шукай "evaluated permission" у `opencode.log`
