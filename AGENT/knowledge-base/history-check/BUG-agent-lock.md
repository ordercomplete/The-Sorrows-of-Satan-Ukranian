# BUG: `agent-lock.json` задекларовано в документації, але не реалізовано в коді v1.3.0

**Тип:** Розбіжність документації з кодом (documentation/implementation gap)
**Версія Агента:** 1.3.0 (чек-аут `c21f3a3`)
**Репо:** https://github.com/ordercomplete/Comfy-smart-lady-agent.git
**Джерело опису:** `Install_Comfy-smart-lady-agent.txt`, Частина I, §2 (рядки 43–46)

---
**Статус: ✅ ЗАКРИТО — реалізовано у v1.4.0 (Варіант Б).**

Після `--apply` у корені цільового проєкту створюється `agent-lock.json`
(типи `copy_full` / `stub` / `root_files`, з хешами), а `sync-agent.py`
набув підкоманди `status` / `remove` / `gitignore`. `remove` переносить
файли у Корзину через `delete_to_trash.py` (не безповоротно); кореневий
`.gitignore` цільового проєкту не змінюється (ігнор — через локальні
`.gitignore` папок). Випадково закомічений `agent-lock.json` та артефакти
`__pycache__`/`*.pyc` прибрані з центрального репо.
---

## 1. Що заявлено в інструкції

Текст §2 стверджує, що після `sync-agent.py --apply` автоматично створюється
`agent-lock.json`, який:

- фіксує всі встановлені файли Агента за типами (`copy_full`, `stub`, `root_files`);
- дозволяє перевіряти статус встановлення (команда `status`);
- дозволяє видаляти **лише** Agent-файли (команда `remove`);
- дозволяє додавати шляхи в `.gitignore` (команда `gitignore`).

## 2. Що фактично в коді v1.3.0 (перевірено по репо)

### a) `sync-agent.py` не створює `agent-lock.json` і не має команд `status`/`remove`/`gitignore`.

Повний перелік CLI-аргументів скрипта (рядки 399–417):

```
--source, --target, --update, --dry-run, --pull,
--apply, --check-update, --repo-url, --version
```

Жодного `--status`, `--remove`, `--gitignore` немає. Після `--apply` скрипт лише
копіює файли за manifest, створює стаби і друкує `git status`/`git diff`
(для інформації) — lock-файл не генерується.

### b) По всьому репо немає жодного коду, що читає або пише `agent-lock.json`.

`git grep` по `*.py *.json *.md *.ps1 *.sh` знаходить лише одну згадку терміну —
сам текст інструкції `Install_Comfy-smart-lady-agent.txt` (рядок 43). У:

- `sync-agent.py`
- `delete_to_trash.py` (реалізує лише механіку Корзини, без lock)
- `update-manifest.py` (працює лише з `manifest.json`)
- `manifest.json`, `manifest-notes.md`, `install.sh`, `install.ps1`
- `test_install.ps1`

ні створення, ні використання lock-файлу не реалізовано.

### c) Прямий наслідок у інсталяції

Після штатного `--apply` у цільовому проєкті файл `AGENT/agent-lock.json`
не з'явився; команди `status`/`remove`/`gitignore` при виклику `sync-agent.py`
недоступні (скрипт завершується помилкою «unrecognized arguments» — аргументи
не описані в парсері).

## 3. Вплив

- Користувач, який дотримується інструкції, очікує, що після встановлення зможе
  перевіряти статус і частково видаляти файли Агента через `remove`/`gitignore` —
  цих можливостей насправді немає.
- Обіцяна «ізоляція» видалення «лише Agent-файлів» на практиці відсутня: єдиний
  безпечний механізм — ручна Корзина через `delete_to_trash.py`, яка не базується
  на lock-файлі.
- Вимога §2 «створюється автоматично після --apply» не підтверджується виконанням.

## 4. Пропозиції щодо виправлення

1. **Варіант А (видалити з документації):** прибрати з §2 згадку про
   `agent-lock.json` і команди `status`/`remove`/`gitignore`, поки вони не
   реалізовані, щоб уникнути введення в оману.
2. **Варіант Б (реалізувати):** додати в `sync-agent.py` логіку формування
   `agent-lock.json` після `--apply` (список встановлених файлів із типами
   `copy_full`/`stub`/`root_files`) та команди `--status`, `--remove`,
   `--gitignore`, що читають цей файл; оновити `manifest.json` (за потреби)
   і тести (`test_install.ps1`).
3. Бажано синхронізувати §2 із фактичною поведінкою інсталятора
   `install.sh`/`install.ps1`, які в поточній версії теж не генерують lock-файл.
