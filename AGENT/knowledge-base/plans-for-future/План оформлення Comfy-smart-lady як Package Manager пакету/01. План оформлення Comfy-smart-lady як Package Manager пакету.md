**План оформлення Comfy-smart-lady як Package Manager пакету**

На основі аналізу архіву: Агент — це не класична бібліотека (немає `import comfy_smart_lady`), а **набір конфігурацій + Markdown-інструкцій + Python-хуків/скриптів + knowledge-base**, який встановлюється в структуру проєкту (`AGENT/`, `.github/`, `.continue/`, `.clinerules/`, `.opencode/` тощо) через `manifest.json` + `sync-agent.py` / install-скрипти.

Найкращий і найзручніший варіант для більшості випадків — **Python-пакет на PyPI** з CLI-командою. Альтернативи (npm тощо) — вторинні.

### 1. Рекомендований підхід: Python-пакет (PyPI)

**Чому саме Python:**
- Усі ключові скрипти вже на Python (`sync-agent.py`, `anti_loop.py`, `str.translate.py`, `delete_to_trash.py`, `agent_startup.py` тощо).
- Вимоги середовища вже включають Python 3.8+.
- Легко зробити кросплатформенний CLI (`csl-agent` або `comfy-smart-lady`).
- PyPI + `pip install` — найпростіший спосіб для користувачів.

#### Крок 1. Підготувати структуру репозиторію (рекомендована)

```text
comfy-smart-lady-agent/                 # новий чи існуючий центральний репо
├── pyproject.toml                      # сучасний стандарт (замість setup.py)
├── README.md
├── LICENSE
├── src/
│   └── comfy_smart_lady/               # або csl_agent
│       ├── __init__.py
│       ├── __main__.py                 # дозволяє python -m comfy_smart_lady
│       ├── cli.py                      # точка входу CLI
│       ├── installer.py                # логіка встановлення (обгортка над sync-agent.py)
│       ├── sync.py                     # перенесений/очищений sync-agent.py
│       └── data/                       # всі файли Агента (AGENT/, agent_config/, шаблони тощо)
│           ├── AGENT/
│           ├── agent_config/
│           │   ├── manifest.json
│           │   └── scripts/
│           ├── .github/                # шаблони
│           ├── .continue/
│           └── ...
├── tests/
└── docs/
```

**Важливо:**
- Файли Агента (Markdown, hooks, knowledge-base) кладемо в `src/comfy_smart_lady/data/` і пакуємо як package data.
- `node_modules` з `.opencode` **ніколи** не включаємо в пакет.
- `__pycache__`, backups, тимчасові файли — виключаємо.

#### Крок 2. `pyproject.toml` (мінімальний приклад)

```toml
[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[project]
name = "comfy-smart-lady"
version = "1.3.0"
description = "Universal coding agent (Comfy-smart-lady) with installable configuration pack"
readme = "README.md"
requires-python = ">=3.8"
license = {text = "MIT"}  # або ваша ліцензія
authors = [{name = "ordercomplete"}]
dependencies = []          # мінімальні залежності (або додати click/typer для CLI)

[project.scripts]
csl-agent = "comfy_smart_lady.cli:main"
comfy-smart-lady = "comfy_smart_lady.cli:main"

[tool.hatch.build.targets.wheel]
packages = ["src/comfy_smart_lady"]
```

#### Крок 3. CLI-команди (що має вміти пакет)

```bash
# Встановити в поточний проєкт
csl-agent install
csl-agent install --dry-run
csl-agent install --force

# Оновити
csl-agent update
csl-agent update --dry-run

# Перевірити стан
csl-agent status
csl-agent doctor          # перевірка середовища (Python, git тощо)

# Показати версію / допомогу
csl-agent --version
csl-agent --help
```

Внутрішня логіка `install` / `update` має:
1. Читати `manifest.json` з пакетних даних.
2. Копіювати/синхронізувати файли в цільовий проєкт (з dry-run).
3. Не чіпати кореневий `.gitignore` хост-проєкту (як зараз).
4. Підтримувати дві «корзини» (`AGENT/trash/` і кореневий `trash/`).

Можна майже повністю перенести існуючий `sync-agent.py` + `install.sh`/`install.ps1` у Python-код CLI.

#### Крок 4. Публікація на PyPI

1. Зареєструватися на https://pypi.org та https://test.pypi.org.
2. Встановити інструменти:
   ```bash
   pip install build twine
   ```
3. Зібрати:
   ```bash
   python -m build
   ```
4. Завантажити на TestPyPI → перевірити:
   ```bash
   twine upload --repository testpypi dist/*
   pip install -i https://test.pypi.org/simple/ comfy-smart-lady
   ```
5. Після перевірки — на основний PyPI:
   ```bash
   twine upload dist/*
   ```

Після цього користувачі зможуть просто:

```bash
pip install comfy-smart-lady
cd my-project
csl-agent install
```

### 2. Альтернативні варіанти (якщо потрібно)

| Менеджер пакетів | Коли має сенс | Складність | Рекомендація |
|------------------|---------------|------------|--------------|
| **PyPI (Python)** | Основний варіант | Середня | **Найкращий** |
| **npm** | Якщо багато JS/TS логіки або хочете `npx csl-agent` | Вища | Можна зробити тонку обгортку поверх Python-пакета |
| **Cargo / Go modules** | Майже немає сенсу | Висока | Не рекомендую |
| **GitHub Template + git submodule** | Якщо не хочете публікувати пакет | Низька | Добре як додатковий спосіб |

**Гібридний варіант (дуже зручний):**
- Основний пакет — Python на PyPI.
- Додатково зробити тонкий npm-пакет, який просто викликає `csl-agent` (через `npx` або як dependency).

### 3. Поетапний план робіт (практичний)

1. **Підготовка (1–2 дні)**
   - Очистити репозиторій від `node_modules`, `__pycache__`, backup-папок.
   - Винести всі канонічні файли Агента в `src/comfy_smart_lady/data/`.
   - Зробити `manifest.json` єдиним джерелом правди.

2. **CLI + installer (2–4 дні)**
   - Реалізувати `cli.py` (рекомендую `typer` або `click`).
   - Перенести логіку `sync-agent.py` в чистий Python-модуль.
   - Підтримка `--dry-run`, `--force`, перевірка середовища.

3. **Тестування**
   - Тести на чистому проєкті.
   - Тести оновлення з попередньої версії.
   - Перевірка на Windows / Linux / macOS.

4. **Документація**
   - Оновити `Install_...txt` → нормальний README з `pip install` інструкцією.
   - Додати приклади використання.

5. **Публікація + CI**
   - GitHub Actions: build + publish на PyPI при створенні Release/tag.
   - Версіонування за SemVer (вже є 1.3.0).

6. **Міграція існуючих користувачів**
   - Залишити старий спосіб (git clone + install.sh) як fallback.
   - У новій версії `csl-agent install` вміти оновлювати проєкти, встановлені старим способом.
