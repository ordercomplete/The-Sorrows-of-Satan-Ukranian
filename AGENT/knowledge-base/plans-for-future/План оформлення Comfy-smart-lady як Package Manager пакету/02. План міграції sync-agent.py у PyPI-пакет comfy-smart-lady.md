**План міграції `sync-agent.py` у PyPI-пакет `comfy-smart-lady`**

Поточний `sync-agent.py` (502 рядки) — це вже добре структурований скрипт з класами (`ManifestParser`, `FileCopier`, `StubGenerator`, `BackupManager`, `GitHelper`) + `argparse` CLI. Міграція полягає не в переписуванні з нуля, а в **рефакторингу під package layout** + додаванні entry-point + пакетуванні даних Агента.

### 2. Поетапний план міграції

#### Етап 1. Підготовка репозиторію (1 день)

1. Створити нову гілку `feature/pypi-package`.
2. Перенести `sync-agent.py` → `src/comfy_smart_lady/sync/engine.py` (поки без змін).
3. Розбити на модулі за класами (див. структуру вище).
4. Винести `_strip_jsonc_comments` у `parser.py`.
5. Прибрати всі `print` з бізнес-логіки → замінити на `logging` (рівні INFO/WARNING/ERROR). Це критично для бібліотечного використання.

#### Етап 2. Адаптація логіки source/target (найважливіший етап)

**Поточна проблема:**  
Скрипт очікує `--source` = шлях до клонованого центрального репо.

**Нова логіка:**

| Режим | Звідки береться source | Як визначається |
|-------|------------------------|-----------------|
| `csl-agent install` / `update` | Файли всередині пакета (`comfy_smart_lady/data/`) | `importlib.resources` / `files()` |
| `csl-agent install --from-git <url>` | Тимчасовий clone | як зараз |
| Старий спосіб (зворотна сумісність) | `--source` шлях | залишити |

**Ключовий код (новий `paths.py`):**

```python
from importlib.resources import files

def get_package_data_root() -> Path:
    """Повертає шлях до запакованих даних Агента."""
    return Path(files("comfy_smart_lady") / "data")
```

У `engine.py` замінити:

```python
# Було:
project_root = Path(args.source).expanduser().resolve()
manifest_path = project_root / 'agent_config' / 'manifest.json'

# Стане:
if source_mode == "package":
    data_root = get_package_data_root()
else:
    data_root = Path(source).expanduser().resolve()
manifest_path = data_root / "agent_config" / "manifest.json"
```

#### Етап 3. CLI-шар (cli.py)

Рекомендую **Typer** (сучасніше за чистий argparse, авто-help, типи).

Мінімальний набір команд:

```bash
csl-agent install [--dry-run] [--force] [--from-git URL]
csl-agent update  [--dry-run]
csl-agent status
csl-agent doctor          # перевірка Python, git, прав тощо
csl-agent version
csl-agent check-update
```

`cli.py` тільки парсить аргументи і викликає функції з `sync.engine`.

Зберегти зворотну сумісність:

```bash
# Старий спосіб продовжить працювати
python -m comfy_smart_lady.sync.engine --source ... --target ... --apply
```

#### Етап 4. Пакування даних (data/)

1. Скопіювати канонічні файли Агента в `src/comfy_smart_lady/data/`.
2. **Виключити**:
   - `.opencode/node_modules/`
   - `__pycache__/`, `*.pyc`
   - `agent_config/backup/`
   - тимчасові `memories_agent/`, логи (або зробити їх опціональними)
3. У `pyproject.toml` явно вказати package-data:

```toml
[tool.hatch.build.targets.wheel.force-include]
"src/comfy_smart_lady/data" = "comfy_smart_lady/data"
```

Або через `[tool.setuptools.package-data]`.

#### Етап 5. Версіонування та метадані

- `__version__` у `__init__.py` = версія з `pyproject.toml` (через `importlib.metadata`).
- `manifest.json` повинен містити ту саму версію.
- При `csl-agent install` записувати в цільовий проєкт файл `AGENT/VERSION` або `agent_config/installed_version.json`.

#### Етап 6. Зворотна сумісність і міграція існуючих проєктів

1. Залишити старі `install.sh` / `install.ps1` (вони можуть викликати новий CLI).
2. `csl-agent update` повинен вміти:
   - виявляти, що проєкт встановлений старим способом;
   - коректно оновлювати його з пакетних даних.
3. Додати команду `csl-agent migrate` (опціонально) — переводить старий layout у новий.

#### Етап 7. Тестування

Обов’язкові тести:

- `tests/test_parser.py` — парсинг manifest з коментарями
- `tests/test_copier.py` — copy_full / stub / self-sync
- `tests/test_backup.py` — створення + prune старих backup
- `tests/test_install_dry_run.py` — повний dry-run на тимчасовій директорії
- `tests/test_package_data.py` — чи доступні файли через `importlib.resources`

#### Етап 8. Публікація

1. `python -m build`
2. Завантажити на TestPyPI → протестувати `pip install`
3. Release на GitHub + автоматичний publish на PyPI через GitHub Actions

### 3. Що змінювати в коді `sync-agent.py` (чеклист)

| Компонент | Дія |
|-----------|-----|
| `_strip_jsonc_comments` | Перенести в `parser.py` без змін |
| `ManifestParser` | Перенести, додати можливість приймати `Path` або `str` |
| `FileCopier` | Майже без змін + підтримка `importlib.resources` як source |
| `StubGenerator` | Без змін |
| `BackupManager` | Без змін (працює тільки з target) |
| `GitHelper` | Без змін |
| `check_update` | Адаптувати: перевіряти версію на PyPI + GitHub |
| `main()` | Розділити на `run_sync(...)` (чиста функція) + CLI-обгортку |
| `argparse` | Замінити / доповнити Typer у `cli.py` |
| Хардкод шляхів | Прибрати `~/repos/...`, зробити package-first |
| `print` | → `logging` |
