# Блок Знань Comfy-smart-lady

## Призначення

Ця база зберігає знання про CodeBase, знайдені рішення та корисні посилання. Допомагає не шукати одне й те саме двічі.

## Структура

### solutions/ — знайдені рішення проблем

Коли вирішуєш складну проблему — записуй контекст і рішення. Тут лежать готові рішення: anti-loop конфігурація та механічні цикли, баг-001 (коментарі в manifest corrupt URL), manager-locale-js-loading, vhs-locale-always-uk.

### api-connect/ — знання про підключення агентів до API

MCP-сервери (підключення через JSON-конфіг агента), стек Cline, GitHub Copilot і LM Studio Code.

### history-check/ — архів закритих багів та нереалізованих планів

Файли типу BUG-*.md, зміст яких втратив актуальність через виправлення описаних у них проблем, а також нереалізовані/відхилені плани. В архівований файл нічого не вноситься, крім заголовка-статуса (✅ ЗАКРИТО / ❌ НЕ РЕАЛІЗОВАНИЙ) на початку. Приклади: BUG-agent-lock.md, BUG-install-discrepancies.md, BUG-001..., symlink-migration-plan.md, «План agent-lock.json — розділення файлів».

### plans-for-future/ — плани на майбутнє

Довгострокові плани оформлення Comfy-smart-lady як Package Manager / PyPI-пакету (5 документів: загальний план, міграція sync-agent.py у PyPI, каркас файлів, зворотний зв'язок, практика в репозиторії).

### code-patterns/ — специфічні патерни коду проєкту (створюється за потреби)

Записуй незвичні або важливі патерни, які зустрічаються в коді.

## Формат запису

```markdown
### Назва проблеми/патерну
**Дата:** YYYY-MM-DD HH:MM. Команда виклику: "шаблон отримання поточного часу" (актуальна на момент запису, перевіряй перед кожним новим записом)
**Контекст:** де в коді зустрічається (файли, функції)
**Рішення/Патерн:** що робити або як працює
**Джерело:** посилання (якщо з інтернету)
```

## Правила ведення

- **Записи не видаляти.** — Старі записи залишаються як історія, щоб бачити еволюцію рішень. Якщо інформація застаріла — додати новий запис з актуальною датою.
- **Актуальна дата й час** — перевіряй перед кожним новим записом. Команда виклику: "шаблон отримання поточного часу"

## Коли додавати

- ✅ знайдені рішення з інтернету.
- ✅ знайшла незвичний патерн у коді поточного проєкту — записати, щоб не шукати знову.
- ✅ вирішила складну проблему — записати рішення.
- ✅ посилання на документацію/статтю, яка дала відповідь.

## Коли НЕ додавати

- ❌ очевидні речі (import os, def foo(): pass).
- ❌ загальновідоме без специфіки проекту.
