**Create React App (CRA) офіційно deprecated з 14 лютого 2025.** React-команда рекомендує для нових проєктів фреймворки або сучасні білдери. CRA залишається в maintenance mode (працює з React 19), але нових фіч, оновлень і активного супроводу немає.

### Що саме сказали в статті React
- Для більшості нових додатків — використовуйте **фреймворк** (Next.js, React Router framework-mode / Remix-наступники, Expo тощо). Вони дають routing, data-fetching, code-splitting «з коробки».
- Якщо потрібен чистий SPA або свій сетап — **Vite**, **Parcel** або **Rsbuild**.
- CRA більше не вирішує сучасні проблеми (waterfalls при fetch, поганий code-splitting, відсутність нормального routing/loaders тощо).

### Що втрачає/втратило підтримку або сильно застаріло (не варто витрачати час на нове вивчення для нових проєктів)

| Технологія | Статус | Коментар |
|------------|--------|----------|
| **Create React App** | Deprecated (лютий 2025) | Переходьте на Vite / Next.js / інші |
| **Webpack як основний інструмент** для нових проєктів | Повільно здає позиції | Залишається в великих legacy-проєктах; для нового — Vite, Rspack, Turbopack, Rsbuild |
| **Snowpack** | Deprecated давно | Рекомендують Vite |
| **Gatsby** (для більшості випадків) | Сильно втратив популярність | Astro + islands майже завжди кращий вибір для контентних сайтів |
| **Класичний Bootstrap / старі CSS-фреймворки** як основний підхід | Втрачає частку | Tailwind + CSS Modules / CSS-in-JS / native CSS features домінують |
| **Чисто client-side React без meta-framework** для production-додатків з SEO/роутингом | Не рекомендовано React-командою | Можна, але доведеться самому збирати routing + data + splitting |
| **Remix v2** | End-of-life (2026) | Remix 3 у бета/перебудові; React Router v7+ взяв на себе багато функціоналу |

Інші речі, які вже не «гарячі»:
- Чистий jQuery / старі SPA-підходи 2015–2018 років.
- Важкі client-only бандли без SSR/SSG/RSC там, де це потрібно.
- Деякі старі state-менеджери в чистому вигляді (хоча Redux Toolkit ще живий у enterprise).

### Що набирає обертів (2025–2026)

**Frontend / React-екосистема**
- **Next.js** (App Router + React Server Components) — досі найбезпечніший дефолт (найбільший hiring pool, екосистема, Vercel).
- **Vite** — стандарт для SPA і кастомних сетапів.
- **TanStack Start** + TanStack Router/Query — швидко росте як type-safe альтернатива з великою гнучкістю деплою.
- **Astro** — відмінний вибір для контентних/маркетингових сайтів (islands architecture).
- **SvelteKit** (особливо з Svelte 5 runes) і **SolidStart** — висока продуктивність і DX для команд, які готові до меншої екосистеми.
- **React Compiler** (стабільний) — зменшує потребу в ручному `useMemo`/`useCallback`.
- **Rsbuild / Rspack** — швидкі Rust-based альтернативи Webpack.

**Загальні тренди**
- **TypeScript** став практично обов’язковим (ексклюзивне використання продовжує зростати).
- **Meta-frameworks** замість «збери сам з CRA + React Router + React Query».
- **Server-first / RSC / streaming SSR** — менше JS у клієнті.
- **Edge computing** (Cloudflare Workers, Vercel Edge тощо).
- **AI-assisted development** (Cursor, Claude, Copilot, v0 тощо) — вже норма, а не хайп. Розробник все більше «архітектор + рев’юер», а не тільки той, хто пише кожен рядок.
- **Tailwind CSS** + сучасний CSS (container queries, cascade layers, view transitions тощо).
- **Bun** як runtime і package manager набирає популярності поряд з Node.js.
- Full-stack / end-to-end ownership фіч (особливо в менших/середніх командах).

### Практичні рекомендації, щоб не витрачати час
1. Новий React-проєкт → **Next.js** (якщо потрібен SSR/SEO/full-stack) або **Vite + React** (чистий SPA).
2. Контентний сайт / блог / маркетинг → **Astro**.
3. Хочете максимальну type-safety і гнучкість → дивіться **TanStack** екосистему.
4. Вивчайте **TypeScript** глибоко, React Server Components, сучасний data-fetching (loaders, server functions).
5. AI-інструменти — обов’язково в робочий процес (але з критичним рев’ю).
6. Не чіпайте CRA для всього нового. Існуючі проєкти на CRA можна поступово мігрувати (є офіційні гайди на Vite, Next.js, Parcel, Rsbuild).

Екосистема стабілізувалася після років «вбивць React». Зараз більше фокусу на зрілості, продуктивності, AI-інтеграції та зменшенні клієнтського JS, ніж на нових фреймворках щотижня. React + meta-frameworks залишаються домінуючими, але з сильнішою конкуренцією від Astro/Svelte/Solid у нішах.
